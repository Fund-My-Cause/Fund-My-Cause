feat(#675): add rate limiting and abuse protection middleware

- Create apps/interface/src/lib/rate-limit/rate-limiter.ts
  - checkRateLimit(): sliding-window counter per identifier, in-process Map store
    (swap for Redis in multi-instance deployments)
  - Automatic expiry cleanup every 60s to prevent memory leaks
  - Pre-built configs: SEARCH_LIMIT (60/min), GENERAL_LIMIT (120/min),
    GRAPHQL_LIMIT (30/min), AUTH_MULTIPLIER (3x for authenticated users)
  - Returns allowed, remaining, resetAt, limit
- Create apps/interface/src/lib/rate-limit/middleware.ts
  - withRateLimit(): HOF wrapping any Next.js route handler with rate limiting
  - getIdentifier(): extracts x-wallet-address > x-forwarded-for > req.ip
  - Authenticated users receive AUTH_MULTIPLIER x base limit automatically
  - Sets RateLimit-Limit/Remaining/Reset/Policy headers on every response
  - Sets Retry-After header and emits throttle metric on 429
  - checkQueryComplexity(): counts nesting depth + fields against maxComplexity
  - checkRequestSize(): rejects bodies exceeding maxBytes (default 100KB)
- Create apps/interface/src/lib/rate-limit/metrics.ts
  - trackThrottledRequest(): increments per-prefix counter + structured log
  - getThrottleMetrics(): returns snapshot of all throttle counters
- Create apps/interface/src/app/api/rate-limit/metrics/route.ts
  - GET /api/rate-limit/metrics — exposes throttle metrics for observability

Closes #675
